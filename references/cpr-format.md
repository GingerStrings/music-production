# CPR 静态读写与适配边界

## 核心方法

在经过识别的已有工程上，保留未知字节，修改已理解的数据，并重建容器长度与引用。使用前应确认目标模板符合下文的结构条件。

用户拥有的已保存模板提供了有效的插件状态、路由、轨道对象和宿主元数据。一次成功的静态往返证明解析器能够还原输入字节；它不能证明每段未知数据的语义，也不能证明宿主实际可加载。

## 观察过的结构

当前实现识别 64 位长度的 RIF2/NUND 容器：

```text
"RIF2" | uint64_be(file_size − 16) | "NUND"
重复：tag[4] | uint64_be(payload_size) | payload
```

通过 `ROOT` 名称找到对应的 `ARCH`，避免依赖“第几个块”这一偶然位置。当前写入器要求名为 `Arrangement1` 和 `Devices` 的配对。

ARCH 中可见带完整类名的对象、复用类名的对象、对象长度与引用。当前变体的引用基准为 archive payload 起点加 8；类引用包含高位标志，对象引用指向对象体。编辑造成后续字节移动时，两类引用都要重定位。

`cpr_archive.py` 将已识别对象与原始字节拆为 `Node`/`Raw`。序列化时记录旧字节到新字节的来源关系，重算长度，再修补已识别引用。重叠对象候选、丢失目标或不一致往返会导致报错。

这里的类发现仍包含启发式分析。正确的失败方式是拒绝陌生结构并调查，不要把一个模板上出现的固定偏移推广到所有 CPR。

克隆对象时，每种 archive 类只保留一次声明，后续对象写向已有声明的类引用；重复的基类声明也需移除，同时重新计算长度和全部引用。使用 `serialize(relocate=True, canonical_classes=True)` 完成该步骤，再调用 `validate_class_registry()` 检查重复声明、冲突版本和向前引用。宿主加载还取决于速度点属性等其他结构。

命名属性具有独立编码。整数 −1 紧接字段名时，会形成类似完整类声明的字节序列；插件状态也可能包含类似引用的字节。已识别的 FAttributes、MTrack 数据、MInstrumentTrack 属性和完整命名属性块须作为不透明区域保留，不参与 archive 类型/引用扫描。不要将 `SummingMode`、`NodePath` 等属性字段误建为 archive 对象。

字符串边界也可能产生假引用：已观察的 v3 `PDrumMapEntry` 含 29 字节标量、带 uint32 长度的名称、uint32 记谱值和另外两个带长度的字符串。前段零字节、名称长度和首字母可能拼成有效对象地址。完整校验该布局后，各字符串的长度与内容应排除出扫描；引用的 8 字节只要与受保护区域重叠就须排除，不能只检查引用起点。

## MIDI 假引用问题

音符/CC 的浮点时间、通道和值组合，可能恰好具有“档案引用”的字节形式。将整个文件中看似引用的八字节一律重定位，会破坏音乐事件。

当前解析器先尝试完整、有边界的 MIDI 解析。只有事件计数、属性长度、记录类型和最终边界全部吻合时，才将该事件区排除出引用扫描。固定长度的参数记录也有相应排除。单靠字节模式匹配或无修改往返不能充分防止这类错误；必须回读比较实际事件。

原生 MIDI 时间单位在当前变体中为每四分音符 480 ticks，以大端浮点数保存。附带 codec 支持 note、CC、program change 和 pitch bend；SysEx、压力及 Note Expression 仍拒绝。空 part 可以恰好结束于 count=0，也可带既有声明标志。

记录公共头为 `>BdBBBHI`：类型、tick、通道、数据字节 1/2、标志、属性数量。每属性含 fourcc、uint16 类型和 8 字节值。弯音的两个字节为 LSB/MSB，转换成 14 位无符号数后减 8192；观察到的宿主记录只有 GLFX 属性。note-off 力度同时写入 note 的尾字段和 VffO，不将源文件的 0 自动改为 64。非零 program change 的宿主独立样本仍不足，见数据工具页的证据范围。

## 速度和拍号

`cpr_timeline.py` 读写已观察到的时间图布局。速度头为 uint32 点数，随后每点 22 字节 `>fddH`：float32 每四分音符秒数、float64 累计秒、float64 原生 tick、uint16 区间形状（0 阶梯、1 到达该点的线性 BPM 渐变）。后接 float32 备用 BPM 和 uint16 模式（0 使用速度图，1 固定速度）。写图时同步计算缓存秒数并切换图模式；float32 量化后的速度用于一致的积分和定位点。

`MTempoTrackEvent` 的 archive 类版本决定后续布局。当前适配器接受 v2/v3；两者均有一份轨道级 fourcc 属性表，v3 还按速度点顺序存放同等数量的点属性表。表以 uint32 数量开头，空表仍占 4 字节；属性值可含数值、字符串或 archive 子对象。类引用对象从首次声明继承版本。未知版本、未知属性类型、截断及对象末尾多余数据均拒绝。

写入器保留轨道级属性及子对象引用。空的点属性表随点数重建；已有非空点属性时，只接受点位置及点数不变的速度修改，保留原属性和引用。移动、增加或删除此类点，需要先实现明确的属性归属规则。例如，从 1 个速度点扩为 8 个时，7 份新增的空点属性表共占 28 字节；省略它们会截断对象。回归测试覆盖增减点数、缺失属性、尾部多余字节、全局子对象保留及类引用版本。

拍号紧凑表为 uint32 点数和 `>iHHQ` 记录：原生 tick、分子、分母、标志。扩展 FAttributes 的 SignatureEvent 数组同步写入。观察到的 `Start` 和 `Bar` 为零基小节序号，`Position` 为原生 tick；两种表示必须相符。当前拒绝小节内部换拍号和未知附加重音布局。

线性变速的积分以 BPM 随拍数线性变化为准，不能对秒/拍进行线性插值。测试覆盖跨变速段提前、变速缓存、两处拍号、弯音符号和 14 位边界。

## 插件状态与路由

插件显示名称、插件唯一标识、组件状态、控制器状态和样本路径承担不同职责。NKI 预置、宿主保存状态和 VST 组件状态的封装不能互换使用。

已有轨编辑器保留 `MInstrumentTrack` 数据并比较完整乐器哈希。另一个窄范围的 [轨道构建器](cpr-scaffold.md) 可以复制明确指定的插件状态，并按私有映射文件替换组件/控制器字节；它不构造厂商 Bank、不运行音源。

新增乐器轨或改变状态的高级适配，还需要处理唯一对象/运行时标识、插件实例标识、总线标识、轨道目录计数、根引用表、automation 目标，以及组件和控制器状态的对应关系。克隆字节后仅更改轨道名称远远不够。

模板中原有的效果器、声像、音量、markers、布局和其他元数据会被保留。确认它们符合本次交付；需要修改时按明确语义实现，不要直接覆盖未知字节。公开前也要检查工程元数据可能包含的身份信息。

## 当前适配器的明确限制

- 已有乐器轨，每轨一个从零开始的 MIDI part，1–128 轨。
- schema v2 支持观察过的多点速度/拍号结构；schema v1 要求固定速度/拍号与模板一致。
- 同时列出所有乐器轨的数据，避免遗漏模板中原有音乐。
- MIDI 插入效果已旁通，轨内没有非空宿主自动化。冲突策略需在扩展适配器中显式实现。
- 调整 MIDI part、乐器轨的时间范围与秒制 Transport 定位点。轨道构建器还按调用方的输出总线重新路由并清除继承的快控绑定；其余 UI/不透明非音乐元数据仍可能来自模板。
- 文件限制 128 MiB，JSON 限制 64 MiB，事件限制 200,000。这些是当前工具的资源边界。
- 只在验证通过后创建新输出。源指纹变化、未知字段、未知 MIDI 类型或结构不符会报错。

如果用户的艺术需求超出上述范围，应扩展并验证工程实现；不要改变创作需求来迁就适配器。

## 扩展时的验证依据

针对目标版本准备用户有权使用的小型模板。默认使用已有文件和可核对的记录。需要在 DAW 界面中做受控小改动并对比保存结构时，必须先有用户明确的前台界面授权；涉及 Computer Use 时还须该项明确授权，遵守 [SKILL.md 的权限规则](../SKILL.md#前台界面与-computer-use默认禁止)。后台插件运行授权不包含前台操作。用户不允许运行软件时，不启动后台插件作替代；缺少界面授权时继续静态验证，并如实标记宿主加载未验证。

按实际修改验证：无修改往返、长度与边界、引用目标、唯一标识、每条事件、插件状态、路由、速度/拍号的多处表示、定位点。改变速度时还要查固定速度备用值和工程元数据，改变拍号时检查紧凑头与扩展属性的一致性。

将结构回读、音源语义、宿主加载和听感验证分别记录。新增测试使用合成数据或可再分发的自建素材，商业模板留在私有目录。

本次扩展的独立只读证据包括 Steinberg 公开 Cubase 6.5/7 演示工程中的弯音记录、Cubase 9.5 演示工程的十次拍号记录，以及已有工程中的多段渐变速度。旧 RIFF 样本用于研究字段；公开写入器仍只接受 RIF2，不因此宣称支持这些旧文件的完整编辑。入口：[Steinberg demo projects](https://o.steinberg.net/en/support/content_and_accessories/demo_projects_cubase_and_nuendo.html)。商业演示音乐和本地插件状态未附入本 skill。
