# 演奏数据与音源实现

本页处理音源响应和时间坐标。表达的形态、强弱走向和技法使用位置由当前音乐决定。

遵循主入口的 [艺术优先与验证边界](../SKILL.md#艺术优先与验证边界)。这些技术资料用于落实音乐决定，不能用于给音乐性打分；常规创作复用已有映射与工具，不为本页内容另建验证脚本或审计报告。

管弦乐的句内动态、呼吸／换弓、声部交接及 CC 编写见 [orchestral-cc.md](orchestral-cc.md)。涉及这些表达决定时读该页，再结合本页的具体音源映射与时间处理实现。

使用主入口列出的音源时，先读取 [主入口列出的对应音源子技能](../SKILL.md#音源子技能)。各库的奏法、CC、连奏模式和近似延迟各自维护；本页继续负责共用的证据、事件与时间处理。TSS 的播放模式与 Lookahead 时序按其子技能处理，避免重复补偿。

## 以实际预置为单位记录证据

同一家厂商的不同库、不同版本和不同脚本模式可能采用不同规则。优先复用实际预置的已有私有记录；只对新用、变更或未知的信息补充依据，不为每首作品重新核验整张表：

| 信息 | 用途 |
| --- | --- |
| 插件标识、库/预置/脚本版本 | 避免套用另一个预置的行为 |
| 载入状态与乐器槽、MIDI 通道 | 确认事件送到正确乐器 |
| 采样覆盖键位、音高移调 | 确认写出的音能发声 |
| 动态、表情、技法、开关 CC | 避免同一个 CC 承担冲突含义 |
| keyswitch 音高、力度分区、提前量 | 正确触发技法 |
| 起音/过渡/短音延迟及模式 | 逐音补偿所需 |
| 信息来源、页码/版本或测量方法 | 区分事实、推断、估计 |

文件名或目录名只能提供线索。预置内部状态、有效的库手册和已有宿主状态能提供更多依据。音源目录存在不证明所有样本可用；插件文件存在也不证明运行时能加载。

已有 CPR 中的插件状态可以整体保留。需要改变音色时，先确认能够正确构造目标插件的保存状态；仅替换显示名称不能完成音色载入。静态路径检查也不能证明授权或插件加载状态。

## CC 与技法

- CC1 在某些模式表示动态，在另一些短音模式可能选择技法或子类型。先查映射，再决定曲线。
- CC11 的作用和处理时机由音源实现决定。连续表情曲线可以插值；承载离散命令的 CC 必须保持命令边界，不能在两个命令值之间扫过。
- 振音控制可能是连续深度、采样交叉渐变或二值开关。不要依据控制器编号猜测语义。
- Keyswitch 通常也是 MIDI 音符，记录实际 MIDI 编号；不同软件的 C0/C1/C2 标注可能不同。将开关音与音乐音区分记录。
- 切换时刻应在目标音符的**触发时间**之前；某些库还需先结束上一音符。检查预备拍、释放时间、重叠和同拍命令顺序。
- 长音进入短音模式后，原有动态曲线可能覆盖固定技法值。按当前映射安排切换与状态恢复；发生具体切换或覆盖异常时，再检查受影响的触发位置和宿主自动化。

附带 CLI 不内置任何厂商的映射值。通用的 MIDI 范围校验无法证明某个 CC 真的选中了 pizzicato 或 legato；这些检查必须读取当前私有音源配置。

## Keyswitch 与控制音的可编辑时值

适用于所有音源的奏法 keyswitch、选槽、模式开关及其他用 MIDI 音符发送的控制命令。交付的工程要方便用户继续演奏和修改，控制音应在钢琴卷帘中容易点选、拖动和调整长短。

- **默认给控制音适量、可见的时值。** 在不改变当前发声、不干扰后续音乐音符或切换、同键重触发的范围内，可以写长一些。可从便于编辑的音乐时值入手，例如十六分或八分音符，再按实际节奏调整；这些是编辑起点，不是所有音源的固定门长。
- **提前量和时值独立安排。** 提前几毫秒发送命令，不等于控制音只能持续几毫秒，也不要自动使用“提前量的一半”。确认是 note-on 锁存、note-off 不撤销或改动状态的开关后，可以让控制音延续过目标音乐音符的起点。
- 按住型、释放时切换、组合按键、音长选择奏法和重复触发要分别核对。延长后检查其是否覆盖了不该生效的音符、与其他控制键组成了新命令，或妨碍下一次同键触发；在实际冲突处结束。
- 不把几毫秒或一两 tick 的脉冲作为通用默认。确有音源规定或紧密切换必须缩短时，只缩短受影响的控制音，说明具体依据，并保留用户可选中调整的编辑方式；不要为了缩短辅助音而移动正常音乐落点。
- 生成脚本也要遵守这项要求。输出后检查控制音时值及相关重叠；不要仅凭 MIDI 能写入、事件顺序正确就忽略可编辑性。此规则不要求拉长正常发声音符，也不覆盖音源以音乐音符时长选择奏法的明确条件。

## 时间坐标

以四分音符为一拍。固定速度下：

```text
advance_beats = advance_ms × BPM / 60000
trigger_beat  = preroll_beats + written_beat − advance_beats
```

预备拍要容纳最早的 note-on、keyswitch 和控制器初始化事件。出现负时间时增加预备拍或检查补偿模型，不将所有事件压到零点。

起音提前量与 note-off 提前量分开记录：

```text
note_off_beat = preroll_beats + written_beat + written_duration
                − release_advance_ms × BPM / 60000
gate_duration = note_off_beat − trigger_beat
```

默认同量提前 note-on 和 note-off，会保持按键时值。若需要特定连奏重叠，可以根据下一音的触发时间计算 note-off；确认它仍产生正时值。重叠时长、是否容许同音重复，以及单音/复音模式，都由实际预置决定，不设统一常数。

每个 CC 单独声明时间处理。某些控制器在声音播放时生效，某些在音符触发时锁存，某些受音源预读模式影响。音符提前不意味着所有 CC 都要同量提前。

变速情况下，使用速度图的“拍→秒→拍”转换跨段求解，不能将整个提前量套在一个局部 BPM 上。附带 schema v2 编译器通过 `music_timeline.TempoMap.advance` 完成转换，支持阶梯速度和随拍数线性变化的 BPM。渐变段采用对数积分与逆函数，note-on、note-off 和 CC 分别计算。

schema v2 的速度图、拍号图使用包含预备拍的工程坐标；score 中的音符仍使用音乐坐标。添加预备拍时同步平移音乐中的速度/拍号变化，保证第一个图点位于零拍。导入 MIDI 后不自动施加延迟或改变音符，音源演奏版另行生成并记录差异。

## MIDI 与目标音源的差异

GM program、打击乐键位、弯音范围和动态控制器需逐项核对。多个 MIDI 端口可以重复使用同一通道号；不能只按通道号合并。钢琴双谱表可合并，另一个声部里附带的和弦播放层应独立保留。不要因辅助轨名称为空而丢掉音符。

弯音数据采用有符号值 −8192…8191；音高变化还取决于接收音源的半音范围。源文件修复、目标音源范围转换和实际插件响应分开验证。将范围从 12 扩为 24 后，所有相关弯音一起缩放，并调整 RPN；仅缩放越界点会改变旋律轨迹。厂商插件可能不响应 RPN，需要设置保存状态里的范围参数。

音源映射版可转换通道、鼓键位、八度输入和控制器语义，保留原谱事件与必要对应关系，不默认另写逐项核对报告。插件显示名称不能代替真实状态，采样盘离线也不能用于推断插件或音色不存在。

## 吉他演奏实现

目标包含吉他演奏时，逐音搬运和换音源只能证明映射完成。检查同拍和弦的起音、力度、时值以及当前音源模式，明确哪些演奏决定来自原谱，哪些已实际写入。

先读取原谱的弦号、品位、扫弦/琶音标记、连线和制音信息，以定弦加品位核对实际音高。链接 TAB 的 MIDI 轨为空时，谱面仍可能含完整指法；不能据此跳过它。和弦符号的自动播放通道也需单独辨认，保留来源记录后按编配决定其用途，不能自动认定为新增乐手。

根据段落区分扫弦、分解、同时拨弦和旋律。扫弦实现应处理上下扫的弦序、跨弦时间、重音、各弦力度和音符释放；分解与已有琶音保留其顺序和节奏，避免二次展开。弦位、同弦占用、换把及制音须与采用的演奏模型一致。选择显式逐弦 MIDI 或插件 Strummer 时，都要核对对应模式与触发命令；Keyboard Mode 的复音能力不能证明真实弦位可行。

柱式记谱或同拍 MIDI 本身不构成错误：同时拨弦、特定音色设计或 Strummer 的和弦输入可以有明确用途。验证需说明该输入如何产生本段需要的动作，不能把所有同拍音符统一随机错开就称为完成吉他演奏。区分电吉他弯音适配、木吉他扫弦实现与实际试听，各自报告完成程度。

有关 Ample 的模式与 Strummer 机制，可查 [厂商演奏说明](https://www.amplesound.net/en/tutorial.asp)；具体参数、音符编号和版本仍需对照本机预置验证。

## 证据等级与验证

以下等级仅标明技术参数的来源。已有依据可直接复用，无需每首作品重新测量；等级和检查结果均不评价音乐性。

`documented`：具体手册或可核对的静态实现支持。记录版本、页码或字段。

`estimated`：有依据的初始猜测，保留估计身份。特别注意首音起音与连奏过渡时延不同。

`measured`：实际音频测量支持。记录音源设置、音高/力度/奏法、宿主延迟补偿、采样率、测量信号与起音判据。文件分析本身不产生这个等级。

`none`：明确没有施加提前量，不能用来掩盖未知延迟。

确认新音源映射、修改时间转换逻辑或排查具体故障时，只按受影响机制检查键位、通道、奏法、控制器覆盖、连奏、补偿或状态重置。常规创作沿用已有配置与工具内置检查，不追加全曲逐音验证。真实乐器演奏可行性按作品交付目标讨论，不能把虚拟音源的限制或某种写作传统直接当作审美标准。
