# 不操作 DAW 界面的离线音频渲染

适用于用户要求试听或音频导出，且会话约束允许执行本地音源和效果器的任务。独立宿主读取已验证的工程数据，在后台运行插件，输出音频文件；无需 Computer Use、Cubase 界面或声卡播放。用户只要求静态处理、禁止启动插件时，不进入本流程。已有音频制作授权继续有效，无需因为采用后台宿主重复询问。

默认禁止前台界面和 Computer Use，遵守 [SKILL.md 的权限规则](../SKILL.md)。音频制作或后台插件授权不包含显示宿主、插件编辑器、播放器或使用桌面自动化。仅运行已确认支持无界面的路径；后台辅助进程隐藏启动，并单独确认插件不会弹窗。若渲染需要界面或交互弹窗，停止该路径、保留日志并报告限制，继续完成其他后台工作；不得自动改用 Cubase 前台或 Computer Use。

## 范围与入口

SV/Synthesizer V 歌声制作、SVP 和插件加载失败后的独立程序路线，另读 [synthesizer-v.md](synthesizer-v.md)。该路线使用进程定向实时录音，须与本页的插件离线渲染分别报告。

这条路径产出“按工程数据离线渲染的音频”。它不能证明 Cubase 已成功打开 CPR，也不能自动保证与 Cubase 导出逐样本相同。

- `scripts/offline_render.py` 提供 VST3 状态包装、MIDI 调度、持续分块渲染及已观察增益规律的基础函数。导入模块不会启动插件。
- 它不负责解析任意 CPR、迁移任意 VST2 预置或重建任意混音图。工程提取器仍须针对已识别的 CPR 结构与插件状态验证。
- 可选运行依赖见 `requirements-render.txt`；纯静态工具无需安装。优先复用已验证的隔离环境。需要格式转换时可使用 FFmpeg。
- 真实状态、插件路径、采样库位置、工程版本信息和渲染缓存放在项目私有工作目录，遵守 [publishing.md](publishing.md)。技能包只收录通用代码与合成测试。

## 从最终工程建立渲染清单

从本次工程取得实际渲染所需的事件、速度、音色、效果器、路由和混音参数，避免重复施加轨道偏移或延迟补偿。这些数据用于生成声音；不另建哈希清单，也不追加每次交付的逐事件审计。

先确认渲染器能表达整个有声信号路径。共享发送、组总线、侧链、多个输出、宿主内置 EQ/Strip、音频轨、冻结轨或未识别的自动化，均需要相应适配。不要静默省略这些处理，再把独奏干声或简化混音当成完整工程导出。可以明确交付受限的诊断片段，完整导出则需解决实际缺口。

渲染使用当前选定的工程数据。修改了会影响声音的事件、音色或效果时，更新对应渲染输入；发生版本混用或声音异常时再定位具体差异，不为每次导出增加全量比对。

## 恢复真实插件状态

优先复用已有插件恢复与渲染路径。首次接入、状态格式变更或出现具体故障时，再选最小片段确认相关加载或控制响应；已确认的路径直接用于制作，不在每次导出前重复测试。每个重型采样器可放在独立子进程中，按内存余量安排并发；保存进度并设置有界超时。插件进程失败时只重试已修正或可解释的条件，保留日志。

几类字节表示需要区分：

| 数据 | 含义 |
| --- | --- |
| CPR 的 `audioComponent` / `editController` | 插件状态负载；需检查对应 UID 与格式 |
| `.vstpreset` / `plugin.preset_data` | VST3 预置容器，含插件 UID 和 Comp/Cont 等块 |
| `plugin.raw_state` | Pedalboard/JUCE 使用的宿主状态包装 |

附带函数面向 Pedalboard 0.9.26。VST3 状态包装使用 `VC2!`、XML 字节长度、`VST3PluginState` XML 和末尾 NUL。XML 的 `IComponent`、`IEditController` 使用 JUCE MemoryBlock 自定义编码；标准 Base64 无法替代。用 `make_vst3_raw_state()` 构造，用 `split_vst3_preset()` 检查运行时预置 UID 与容器边界。VST2 状态迁到 VST3 要单独验证，不能直接换标签。

```python
from pathlib import Path
from pedalboard import load_plugin
from offline_render import make_vst3_raw_state, split_vst3_preset

plugin = load_plugin(config["plugin_path"])
assert plugin.is_instrument
# 某些插件需要先准备音频处理，再恢复状态；这一行为应在短片段中验证。
plugin([], duration=0.05, sample_rate=sample_rate, buffer_size=512, reset=False)
plugin.raw_state = make_vst3_raw_state(
    Path(config["component_path"]).read_bytes(),
    Path(config["controller_path"]).read_bytes() if config.get("controller_path") else b"",
)
runtime_uid, chunks = split_vst3_preset(plugin.preset_data)
assert runtime_uid.upper() == config["uid"].upper()
```

`raw_state` 是宿主相关表示，依赖升级后应重做小型探针。插件可能规范化或更新内部状态，因此运行时重新保存的字节变化需要解释，不能直接推定加载失败。分别核对源状态未变、运行时身份/关键参数、采样可用性和实际发声。插件缺失或样本离线不应触发未经请求的音色替换。

## 时间与连续渲染

使用工程速度图将事件拍位换算为秒；变速区间按 `60/BPM` 积分。新版静态工具已有 `TempoMap.beat_to_seconds()`。旧适配器或其他时间图可向 `schedule_midi()` 提供等价回调；固定速度时可用 `beat * 60 / bpm`。演奏数据已含提前量时，不再重复移动事件。

每个分块使用 `[left, right)` 时间窗，交界事件恰好分派一次，传给插件的是块内相对时间。同刻 note-off 先于控制事件与 note-on，控制事件保留明确的先后次序。改变 MIDI 通道、初始 program 或奏法命令可能改变已保存的音色行为，应按真实状态核对。

连续分块保持同一个插件实例与 `reset=False`。重新初始化、反复载入预置或每块重置都会打断长音、踏板、连奏及效果尾音。`render_instrument()` 检查通道、帧数与非有限数值；它接收已初始化的插件，不自行决定加载权限。

下面仅生成一条乐器干声；`beat_to_seconds`、事件、尾音时长与路径来自当前项目已验证的数据：

```python
import soundfile as sf
from offline_render import schedule_midi, render_instrument

messages, timing_report = schedule_midi(track["events"], beat_to_seconds, end_beats)
frames = round((beat_to_seconds(end_beats) + tail_seconds) * sample_rate)
audio = render_instrument(plugin, messages, frames, sample_rate, block_frames=4*sample_rate)
sf.write(output_path, audio.T, sample_rate, subtype="FLOAT")
```

安排正时值的渲染事件，明确处理零时值 note 和终点消息。不要把落在输出终点的 note-off/CC 静默丢掉。通常先结束音乐事件，再给足音源释放与效果尾音；只有在实测尾部已衰减后，才裁到定位点。不能在任意分块边界发送 All Notes Off。

高分辨率力度在 CPR 中保留。独立 MIDI 宿主若只接受 7 位力度，按归一化值量化，记录误差；note-on 保持正力度，release 可为零。事件时间积分正确也不代表插件收到了宿主 tempo、transport 或拍号。依赖这些信息的 LFO、同步延迟、节拍器或特殊预读功能需要额外支持，否则写明差异。

## 复现信号路径

简单立体声乐器轨的一种信号路径如下。

`乐器音频 → 前置增益/自动化 → 各插入效果器 → 后推子/自动化 → 声像与路由 → 总和 → 母线处理`

按实际工程确定次序。不要把前置增益移到效果器后方：压缩、动态 EQ、饱和或 ducking 会因输入变化产生不同结果。声像规律、发送位置与母线处理也需匹配；居中立体声的特例不能外推到任意声像。

自动化按原生参数域、时间锚点及其曲线插值。按拍位存储的曲线需要把采样点的秒位置还原为拍位；按秒或采样位置存储的曲线保留相应坐标，不随速度图额外移动。保存值可能经 float32 舍入；音频应使用回读到的实际值。首点之前的状态需包含初始值，不能让插值函数把尾声第一个低值沿整曲向前铺开。离散命令不做平滑插值。

helper 中的增益函数限定于已观察的 Cubase 15 默认 +6 dB 推子刻度和 InputGain。更换版本、刻度或值类型后须用保存实例验证。不要把 `raw / 32767` 直接当作线性音量，也不要猜测 dB 曲线。

效果器处理还须核对输出帧数、报告的 latency 与残留尾音。部分宿主处理接口会暂存样本，返回长度可能小于输入；用已验证的冲刷/对齐方式补齐，检查是否已由宿主补偿，避免再次平移。延迟补偿和音乐性的起音提前分开记录。不要把固定填零或统一裁掉一段当作所有插件的处理方法。

## 缓存与末期混音

缓存注明所属声部、生成版本及信号链位置，例如音源输出或插入效果器后的音频。根据本次实际修改决定哪些声部需要重渲；不计算源文件或缓存的哈希，不建立逐文件审计清单。

只有后推子或母线的线性增益变化，且其后不存在会改变响应的处理或分支时，可以对已处理 stem 数学缩放；时变增益按完整自动化计算。若后方有压缩器、限制器、侧链或共享效果，必须重新通过受影响路径。源 stem 在某时段已被零增益清除时，无法通过倍率恢复；应使用未清除的中间音频或重渲。

如果仅改变这类末级增益，保存所用分轨和新增益的对应关系，按新设置生成成品，避免把未更新的混音作为最终输出。

## 按具体问题调整动态

管弦乐的表达设计见 [orchestral-cc.md](orchestral-cc.md)。下面的方法用于解决具体发声问题或用户反馈，不属于常规交付清单。遵循 [艺术优先与验证边界](../SKILL.md#艺术优先与验证边界)：信号测量只用于定位相关实现问题，不得作为音乐性验证或自动审美评分。

根据问题选择需要的方法：

- 用当前保存预置做受控的同音、同力度 CC 对照，确认真实音量/频谱响应。不要凭“CC1/CC11 通常表示什么”推断当前奏法。
- 怀疑控制器没有生效或被覆盖时，检查相关发声位置的有效控制值。点数、曲线起伏和声部间的差异不能证明音乐表现力，不据此强制增加变化。
- 分别看音头、句峰、释放及声部进退；音源慢起音与混响会让声压峰滞后于 CC 峰值。
- 对原曲或既有工程的修订，核对是否误删了原表情、回应节奏、休止、持续音或有意的半音色彩。乐器音域合法、音符不重叠仍不足以证明配器成立。
- 用户需要对照时，可提供音量相近的旧/新片段或独立声部供其试听，标明片段范围。助手不根据 LUFS/LRA/RMS 替用户判定听感，也不记录用户是否听过。

这些判断随作品、乐器和奏法变化；不把某首曲子的乐句、调性、CC 数值范围或编制写成固定模板。

## 导出、复核与报告

先以浮点 WAV 保留中间声部与混音，根据作品目标决定最终增益和输出格式。常规输出读取一次，确认存在实际音频、歌曲与尾音未意外截断、所需素材齐全；处理读取失败、全静音等明显数据问题。用户要求响度指标或出现具体峰值、声道问题时，再做对应测量，不默认执行完整信号审计。

格式转换后确认产物可读取；发现转换错误时只排查相关格式和片段。全曲已成功生成才报告全曲完成，片段交付标明范围。量化误差和逐样本比对不作为常规交付步骤。

交付说明只写实际产物、必要使用方法和影响使用的限制。试听及听感由用户自行判断，不设听审完成状态，不填写“已听／未听／听审通过”。不记录工程或音频哈希，也不附加未执行项目的审查表。

Pedalboard 文档说明了 VST3 插件处理接口及已知兼容限制。恢复状态和转换推子数值时应匹配宿主版本、插件类型与工程使用的增益刻度。[Pedalboard VST3/MIDI API](https://spotify.github.io/pedalboard/reference/pedalboard.html) · [插件兼容性说明](https://spotify.github.io/pedalboard/compatibility.html)
