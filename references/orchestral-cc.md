# 管弦乐演奏与 CC 编写

适用于管弦乐 MIDI 的创作、续写、改编和表情修订。先确定声部在乐句里的作用，再选择当前音源能够实现的演奏动作与控制数据。阅读本页时结合 [performance.md](performance.md) 的音源证据和时间坐标；需要音频时接入 [offline-render.md](offline-render.md)。纯记谱任务按谱面表达处理，无需附加 MIDI 或插件验证。

本页遵循 [艺术优先与验证边界](../SKILL.md#艺术优先与验证边界)。CC 与奏法服务于音乐表达，事件统计、曲线形状和工程回读不能验证音乐性；不为每次创作建立表达验收脚本、逐句审计或音乐性评分。

## 先确认控制器实际控制什么

按实际预置和奏法使用 velocity、动态、表情、振音及技法选择的映射，复用已有来源，只补充新用、变更或未知的信息。区分持续生效、仅在起音锁存、连续变化和离散选择；同一预置切换奏法后也可能改变响应。未知映射如实保留不确定性，不凭编号填曲线，也不为每首作品重做响应验证。

- velocity 可能影响起音、力度层、连奏过渡或技法。长音和短音分别确认，不能把所有力度变化交给同一个控制器。
- 若当前库通过动态控制器改变采样层或音色，按所需的演奏强度写入；若表情控制器主要改变电平，用于句内支撑、退让和收束。两者配合时检查是否叠加成过度衰减或抽吸，不默认画成相同曲线。
- 振音、气声、弓压等只使用当前预置实际支持的映射。依乐器、风格和句意决定是否变化；采样自带的演奏变化也要计入。
- 平衡声部的轨道推子、音源动态和乐句表情分开处理。需要改变音色强度时，单独推高总音量可能无法达到目标。

## 以乐句安排表达

在生成事件前，为相关声部确定进入方式、句内方向、与其他声部的关系及退出方式。可以直接写在现有乐曲数据或简短工作记录中，无需逐音填表；重复乐句可以复用意图，再检查上下文。

| 决定 | 要落实的内容 |
| --- | --- |
| 声部作用 | 主线、回应、内声、低音或织体，以及何时接手或退让 |
| 起句 | 柔入、明确起音、承接前句或有意突入，所需奏法与起始状态 |
| 句内方向 | 渐强、渐弱、保持、局部重音；需要句峰时再决定位置和宽度 |
| 连接与空间 | 连奏、分弓、吐音、呼吸、休止，以及与其他声部的衔接 |
| 句尾 | 收束、持续、交接或截断，以及释放尾音是否需要保留 |

稳定长音、弱奏背景、齐奏和共同渐强都可以是明确的音乐决定。持续表达可以跨越多个音高，不要求每个音符各画一个拱形；也不强制每句设置高潮。需要的变化应来自乐句、发音和声部关系，随机摆动只能作为有依据的细节处理。

## 按乐器与奏法处理

### 弦乐

- 长音与连奏：考虑弓头、持续支撑、换弓和句尾。保持跨音的乐句连续，按实际连奏机制安排重叠、过渡力度和动态；不要每次换音都把表情降到零。独奏换弓与弦乐组交错换弓分别处理；持续织体可以保持整体稳定。
- 分弓、短弓与拨弦：优先落实奏法、重音、音长、力度层和重复音行为，再判断持续 CC 是否有作用。确认短音模式中的控制器是否承担技法选择，避免表情曲线扫过其他技法。
- 需要可闻的换弓、重奏、弓向或特定音头时，选择支持该动作的奏法或事件组织；只改变音量无法保证产生对应动作。已经录入采样的音头和衰减无需机械重复塑形。

### 木管

- 起音、吐音和连线应与句子一致，检查首音与连奏过渡的不同响应。持续气息中的支撑和收束依音区、动态与音色决定。
- 需要实际换气时，结合乐句修改 note-off、下一个 note-on 和休止；只拉低表情不能保证采样停止或重新起音。避免按固定时长给所有木管插入同样的呼吸。
- 区分独奏呼吸、多人轮换和有意连续的声音设计。保留连贯织体时，可在声部之间交接或交错呼吸，按任务目标决定写实程度。

### 铜管

- 区分音头能量、持续支撑、音色强度与句尾释放。重音后保持、推进和退让可有不同形状；持续渐强需检查音色是否随强度变化。
- sfz、marcato、录制好的渐强等奏法先核对自身包络和触发条件，再决定附加动态。避免将已有重音包络叠加成不需要的二次起伏。
- 处理呼吸、分句和合奏层次，按实际乐器与写作目标判断持续能力，不用统一的 CC 值或时长代表整个铜管组。

### 打击乐、竖琴及其他击弦／拨弦声部

- 对单次敲击或拨弦，先检查 velocity、音区、击奏位置、制音和采样衰减。持续 CC 是否改变已发声的音，以当前库为准；普通衰减音不能靠音量曲线保证获得真实的重新激发或滚奏。
- 滚奏、震音和持续摩擦等奏法单独核对动态与释放机制。若由重复击奏构成，按音乐决定击奏密度、重音和衔接；若使用录制滚奏，检查内置变化，避免重复塑形。

## 声部之间的关系

分别判断旋律、回应、内声和低音的方向。共同渐强或齐奏可以共享音乐目标，但要按各预置的响应、音区与织体校准；同一数值未必产生同样的力度或响度。不要为了曲线看起来不同而制造无意义的错位。

同一接收音源和 MIDI 通道内，普通 MIDI 1.0 CC 是通道级控制；给重叠音符分别绘制曲线仍可能互相覆盖。需要同时独立表达的 divisi 或复调线条，应分配到独立接收通道／乐器实例，并核对路由。只拆轨但继续汇入同一音源通道不会形成独立控制。使用逐音表达时，确认宿主、插件和导出适配器都支持对应机制；Cubase 中存为 Note Expression 的普通 MIDI CC 仍受通道范围限制。参见 [Steinberg：MIDI Controllers](https://www.steinberg.help/r/cubase-pro/15.0/en/cubase_nuendo/topics/note_expression/note_expression_midi_controllers_c.html)。

修订已有工程时，先读取原有表情、节奏回应、休止和声部走向；保留应继承的处理，并记录有意重写的范围。发现疑似和声、音区、时值、声部进行或密度问题时，先对照原曲意图和本次修改范围；确认属于实现错误或已授权的音乐修改后，再调整相应数据。保留有意的持续音、紧密音程与不协和，不能靠 CC 掩盖已确认的实现错误。

## 写入真实事件与状态

- 在首个需要的触发前建立有效初值，包括奏法及其依赖状态。从中段试听或分块渲染时恢复正确的先前状态，避免靠上次播放残留；带前导或状态恢复的方法见离线渲染流程。
- 先确定关键位置和保持区间，再按目标格式、音源平滑能力和音频结果选择事件密度。MIDI CC 点之间不会天然生成任意曲线；需要时显式采样，保留转折和离散命令边界。不要用固定点数或统一采样间隔代替表达判断。
- 核对首点之前、末点之后、休止跨段和奏法切换时的有效状态。已有宿主自动化、Expression Map、MIDI 插件或重复控制器源可能覆盖新数据；不要让远处两个点的插值意外改变整段乐句。
- 音符提前量与 CC 生效时间分别处理，见演奏页。切换后的动态和表情要符合新奏法，回到原奏法时检查是否需要恢复原状态。
- note-off 后可能仍有释放采样或尾音。重置表情、切换奏法和下一句的初值可能影响它们；结合预置机制安排，不默认立即清零。音量降至零也不等于结束 MIDI 音符。
- 交付音频使用最终工程对应的数据，复用写入工具内置的保存检查。只有出现漏音、奏法异常或控制器覆盖等具体问题时，才回读相关片段，不默认另写全曲核对脚本。把原有曲线重采样成更多点，不能据此宣称提升了音乐表现力。

## 音乐判断与技术排查

音乐判断结合乐句推进、声部关系、风格、上下文与创作意图展开，保留不同表达选择。不得通过工程测试、规则命中率或数据指标宣布作品具有音乐性，也不得因曲线平直、声部使用相同曲线或变化次数少，就判定缺乏表现力。

技术排查只回答具体实现问题：

- 出现漏音、错奏法、意外截断或控制器覆盖时，检查受影响的事件、状态及前后衔接；问题解决后停止。
- 新用或变更的预置缺少映射依据时，先查对应资料；确需执行插件且会话允许时，用最小片段确认相关控制响应。已有配置不例行重测。
- 用户需要听感对照时，提供相关独奏或混音片段，保留内部动态；响度匹配只用于便于比较，不能据此得出哪个版本更有音乐性的结论。试听及听感由用户掌握，助手不记录试听状态，也不创建听审通过状态。

本规范不设置通用 CC 数值区间、固定乐句长度、最低变化次数或“每音必起伏”的指标，不要求分层验证报告。按音乐意图实际写入所需演奏处理，交付用户要求的工程、音频或谱面，再根据音乐反馈修改。
